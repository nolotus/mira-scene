# 录屏拍摄脚本（3–5 分钟）

> 题目要求这段录屏必须展示：文字或语音互动、角色状态与画面变化、**在角色说话时成功打断**、所选的多模态能力、**至少一种失败或降级状态**。
> 本脚本按顺序覆盖以上全部，并在末尾给出「镜头 → 要求」对应表，方便评审逐条核对。

## 拍摄前准备（不计入时长）

```bash
bun install          # 依赖
bun run dev          # 前端 5173 + 服务端 8787，一条命令
```

- 默认 **Mock 导演**，**不需要任何密钥**即完整可跑（画面左下角应显示 `Mock 导演` 与零密钥提示）。
- 浏览器窗口按 **375 × 700 左右**摆好（移动端优先是本项目的主要形态），不要全屏拉伸。
- 开好 DevTools（Network 面板）备用；关掉系统静音，录屏要能听到角色语音。
- 真模型对照两种开法（**录屏推荐第一种**，两屏能同框看出差别）：
  - **按会话切**：服务端照常 `bun run dev`，浏览器打开 `http://localhost:5173/?director=live` —— 只影响这个标签页的会话；另开一个不带参数的标签页仍是 Mock 导演。没配密钥时状态条会写「请求真模型，但服务端未配置密钥，已回落 Mock」，不会静默变成 Mock。
  - **整机默认 live**：另开一个终端 `DIRECTOR=live DEEPSEEK_API_KEY=... bun run dev`（所有会话都走真模型；`DIRECTOR=mock` 可强制压回 Mock）。
- 成本提醒：`?director=live` + 服务端有 key 才真的产生模型调用费用；Mock 路径零成本，除「真模型对照」那段，其余分镜都用默认（不带参数）录制即可。

## 分镜

### 0:00–0:20　开场：一句话 + 一条命令
- 口播：这是 72 小时 take-home，实时互动场景，角色 Mira 在打烊前的咖啡馆等人。
- 画面：终端里 `bun install && bun run dev`，然后浏览器打开 5173。
- 要点：**零密钥**，左下角显示 `Mock 导演`，说明为什么 Mock 是主路径而不是凑数。

### 0:20–1:10　第一轮：文字互动 + 四种状态
- 输入「你今晚一个人？」 发送。
- 画面要点：状态依次可见 —— **待机**（呼吸）→ **倾听**（前倾/注意）→ **思考**（视线偏移、画面降饱和）→ **说话**（口部与头部动作 + 字幕逐字推进）。
- 口播：字幕是流式增量，不是整段铺满。

### 1:10–1:50　由对话内容触发的视觉事件
- 输入「外面还在下雨吗？」。
- 画面要点：**闪电 + 雨势加大 + 镜头轻抖 + 角色打了个寒颤 + 望向窗外**。
- 口播重点：这些不是定时器轮播，是**由这一句台词的内容命中 beat** 才触发；换一句无关的话不会出现。

### 1:50–2:40　语音输入 + 语音回复 + 字幕同步
- 点麦克风（或按住说话），说「你在等谁？」
- 画面要点：底部出现「正在朗读：…」与字幕同步推进，说明语音落点与字幕是对齐的。
- 口播：STT 用浏览器能力，TTS 走可替换的 Provider（默认系统语音，零密钥）。

### 2:40–3:20　★ 打断（本题核心，连做两次）
- 在角色**正在说话**时开口/点击打断。
- 画面要点（逐条对得上题目要求）：
  1. 语音**立即**停止；
  2. 字幕**不再增长**，后面的句子不会继续出现；
  3. 角色动作/镜头立刻停在当前状态，不会把未播放的演出播完；
  4. 状态切回**倾听**并开始处理新输入。
- 口播：再做一次，证明不是偶然；说明客户端用 `epoch` + `turnId` 双闸门丢弃旧轮事件。

### 3:20–3:50　★ 证明「迟到的响应不会回放」
- DevTools → Network 调成 **Slow 4G**（或 Add custom profile，加 2s 延迟）。
- 发起一轮 → 在角色说话时打断 → 观察 Dock 上 **「丢弃迟到事件 N」** 自增。
- 口播：这是护栏的**可见证据**——旧轮的 SSE 事件还在往回飞，但进不来 reducer，画面既不回退也不重播。

### 3:50–4:20　失败与降级（题目要求「至少一种」）
任选其二即可：
- **断线**：直接 Ctrl-C 杀掉服务端 → 顶部出现可重试提示，点「重试」在服务端恢复后能接着聊；
- **麦克风被拒**：浏览器弹权限时点「拒绝」→ 有明确提示，且**文字输入仍然可用**；
- **不支持语音识别**：换 Firefox 演示（若无 Web Speech）→ 降级为纯文字并给出说明。

### 4:20–4:50　真模型对照（可选，20 秒足够）
- 切到 `DIRECTOR=live`，同一句输入。
- 口播：换了导演，**渲染路径一行没改**；模型输出先过白名单校验才变成指令，非法值直接丢弃。

### 4:50–5:00　收尾
- 快速扫一下 README 的结构：系统结构、打断流程、指令设计、取舍、已知问题、投入时间、再给两周怎么演进。

## 拍摄纪律（容易翻车的点）

- **不要快进、不要剪掉中间的停顿**——评审要看你真的在等流式输出和语音。
- 每段口播**先说要证明什么，再操作**，避免看完不知道在证明什么。
- 打断那一段**一定要连做两次**，并且第二次在语音说到一半时打断，才能看出「立即停止」。
- 失败演示要**当场发生**（真杀进程/真点拒绝），不要事后补口播。
- 录完自查：把声音关掉看一遍，画面本身能不能看懂发生了什么。
